What TOURney Is

Multi-tenant tournament SaaS PWA. Static HTML/JS frontend deployed on Vercel. Supabase for auth, database, realtime, and edge functions. GitHub as the source of truth — every push to main triggers an immediate Vercel production deploy. No framework build step. All Claude Code agents (Planner, Execution, Bug Review) operate directly on this pipeline.

No framework. tourney-init.js as init layer. Vercel CDN delivery.

Edge Functions — Auth Patterns
  • send-push — Requires Authorization header. Validates user via anon client. Verifies tournament ownership or admin membership via service role. Origin restricted to *.greenskeeper.studio. BUG: .select('id') on tournament_admins — no id col
  • platform-action — Requires Authorization. Validates user via anon client. Platform owner check via PLATFORM_OWNER_EMAIL env var. Service role for privileged writes. Origin regex validated.
  • send-install-email — Webhook secret auth (SEND_INSTALL_EMAIL_SECRET). Called by Supabase DB webhook on player insert. Service role for tournament lookup. Secret not set in prod yet
  • log-client-error — Accepts error payloads from client bug-fab.js. Writes to Supabase. No user auth required (public error logging).
  • create-checkout — Stripe checkout session creator. Stripe secret held server-side. Not live — keys unset.
Security Headers (vercel.json)
  • HSTS: max-age=63072000; includeSubDomains; preload — 2-year HSTS with preload. Correct.
  • X-Content-Type-Options: nosniff — present on all routes.
  • X-Frame-Options: DENY — clickjacking protection present.
  • Referrer-Policy: strict-origin-when-cross-origin — correct.
  • Permissions-Policy: camera, microphone, geolocation blocked. Payment self-only.
  • CSP: Applied to *.html only. Allows unsafe-inline for scripts (required by current inline JS architecture). cdn.jsdelivr.net in script-src. unsafe-inline weakens XSS protection
  • Cache headers: no-store on .html and .json. SW served no-store. Assets (CSS/JS/PNG) have no explicit Cache-Control — rely on Vercel CDN defaults.
Service Worker — Cache Strategy
  • Cache name: tourney-v37 — manual bump required on every deploy that changes precached files.
  • Precache list: 25 entries — manually maintained. Agent-added files not auto-added.
  • Supabase passthrough: SW skips all *.supabase.co requests. Correct.
  • JSON bypass: SW skips .json files — artifacts always fresh. Correct.
  • Network-first: bug-fab.js and tourney-init.js use network-first. Correct — these change frequently.
  • Risk: Agent deploys HTML/CSS/JS changes without bumping CACHE version = PWA users get stale assets until manual cache clear. No automation for version bump
Claude Agent Workflow — Git + Vercel
  • Commit flow: Planner dispatches → Execution worker commits directly to main → push triggers Vercel prod deploy instantly. Zero human review gate between agent commit and live URL.
  • Branch protection: None. Agents can force-push, rewrite history, or deploy broken code with no friction.
  • Staging environment: None. Agents always test against production. A broken agent fix ships immediately to real players.
  • CI gating: 7 workflows run (ci.yml, test.yml, typecheck.yml, lighthouse.yml) but Vercel deploys on push regardless of workflow pass/fail. Tests are informational, not blocking.
  • Worktree accumulation: .claude/worktrees/ inside repo — nested worktrees found (e.g. dazzling-volhard-3f903d/.claude/worktrees/...). These pollute grep results, inflate repo size, and confuse future agents reading the codebase.
Claude Agent Workflow — Supabase MCP
  • Available to agents: mcp__claude_ai_Supabase__execute_sql, apply_migration, get_logs, list_tables, and 15+ other tools.
  • No isolation: All Supabase MCP calls target production. No Supabase branch/preview for agent work. A bad migration applied by an Execution worker is instant, permanent, and hits real data.
  • No migration review gate: Agents can apply_migration without Rob approval. The only safeguard is the agent's own judgment.
  • Logs accessible: get_logs lets agents diagnose Supabase edge function logs directly — this is a positive capability.
Strengths
  • All secrets (VAPID, service_role, RESEND, STRIPE) in Supabase/Vercel env vars — zero committed secrets found.
  • Edge functions authenticate callers before any privileged operation. Origin validation on send-push and platform-action.
  • SW correctly passes through all Supabase API/realtime calls — no caching of live data.
  • 7 CI workflows in place — infrastructure thinking is solid.
  • JSON artifacts always served fresh (no-store + SW bypass).
  • 12 clean, unambiguously ordered migrations.
  • Network-first for frequently-changing scripts (tourney-init.js, bug-fab.js).
  • CSP configured (even if unsafe-inline — it's there).
  • Supabase MCP gives agents strong diagnostic capability (logs, SQL, tables).

SW Cache Auto-Bump
Every agent deploy risks serving stale cached assets to PWA users. A GitHub Action that auto-increments the CACHE version in sw.js on every push eliminates this risk. No agent needs to remember to bump — it happens automatically.
Build: Add a step in ci.yml: sed -i "s/tourney-v[0-9]*/tourney-v$(date +%s)/" sw.js and commit. Or use a numeric counter stored in a file.

Add SW cache auto-bump to ci.yml
Read .github/workflows/ci.yml. After the checkout step, add a step:
- name: Bump SW cache version
  run: |
    NEW_VER="tourney-v$(date +%s)"
    sed -i "s/const CACHE = 'tourney-v[0-9]*/const CACHE = '$NEW_VER/" sw.js
    git config user.email "ci@greenskeeper.studio"
    git config user.name "GKS CI"
    git diff --quiet || git commit -am "ci: bump SW cache version"
    git push
This runs on every push, auto-increments the CACHE key using a Unix timestamp, and commits the updated sw.js.
