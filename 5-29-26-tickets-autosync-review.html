Eliminate manual qa-index.json maintenance — ticket HTML files should auto-discover and appear in the platform Artifacts tab without AI or human intervention.

Section 01
Review — Current State
Evidence-based audit of the artifact sync gap: how tickets get created vs. how the platform discovers them.
The Problem (Platform Bug Report)

Rob's request: "The tickets line item should always match the HTML. And the loading of the tickets should be automatic via the site. Not by AI making the update."

Root cause: platform.html Artifacts tab fetches only /qa-index.json at runtime (platform.html:1413). That file is hand-maintained by AI skills. Any ticket HTML file created in the repo root is invisible to the platform until a separate manual step inserts an entry into qa-index.json.

Evidence — HTML Files vs. qa-index Entries
  • 22 ticket HTML files exist in repo root matching *-review.html pattern (confirmed via ls *.html | wc -l)
  • 47 entries in qa-index.json — the gap exists because some entries are non-HTML artifacts (plans, audits, runbooks) and some HTML files have multiple index entries (e.g. stage promotions)
  • However the count mismatch is not the core problem — the process dependency is: every new ticket HTML requires a matching AI-written qa-index.json edit to appear in the UI
  • If an agent creates a ticket HTML but fails, times out, or skips the index step, the file is silently orphaned
Evidence — How platform.html Loads Artifacts (platform.html:1410–1482)
  • loadArtifacts() at line 1410: does a single fetch('/qa-index.json', {cache:'no-store'})
  • Parses d.entries array → sets allEntries → calls renderArtifactTickets()
  • Zero filesystem discovery. No glob, no directory listing, no GitHub API call. 100% dependent on qa-index.json being correct
  • Re-fetches on tab visibility change (platform.html:884) — so it's "live" in that sense, but still bound to the JSON registry
  • Empty-state hint reads: "Run /tourney-review or append to qa-index.json" (platform.html:1408) — explicitly instructs manual update
Evidence — vercel.json Routing for Ticket Files
  • Ticket HTML files are served directly from repo root — Vercel serves static files without explicit rewrites for most tickets
  • Some older tickets have explicit permanent: true redirects in vercel.json (e.g. /5-6-26-claude-review → /platform/5-6-26-claude-review) — these were added manually too
  • Newer tickets rely on Vercel's default static file serving: /5-29-26-ux-review.html is accessible at that path without any rewrite entry
  • No API route, no Edge Function, no serverless function exists that could enumerate files at runtime
  • JSON files served with Cache-Control: no-store, must-revalidate — so qa-index.json is always fresh on fetch, which is correct
Evidence — No Build Scripts Exist
  • scripts/ directory does not exist in repo root
  • package.json has scripts: typecheck, test, test:e2e — no build step, no pre-commit hook runner, no index generator
  • .git/hooks/ contains only sample files (disabled by .sample suffix) — no active pre-commit hook
  • No CI/CD config file found (.github/workflows/ not present in root listing)
Strengths
  • qa-index.json has Cache-Control: no-store — platform always gets latest version without stale cache issues
  • loadArtifacts() re-fires on tab visibility change — live refresh works correctly once index is updated
  • qa-index.json schema is well-structured with rich metadata (category, stage, tags, summary, url, file) — good foundation for auto-generation
  • Ticket HTML files follow a consistent naming convention: {M-D-YY}-{axis}-review.html — parseable by a script
  • HTML files already embed <title> tags with the ticket title — auto-extraction is straightforward

Section 02
Plan — Options & Recommendation
Three viable approaches evaluated. One recommended based on zero runtime cost and no new infrastructure.
Strategic Priorities
  1. P1 — Build-time script (Recommended): Node.js script scans *.html, extracts metadata from <title> tags and HTML comment markers, regenerates qa-index.json and patches vercel.json rewrites. Runs as git pre-commit hook. Zero runtime cost, no new infrastructure, works offline.
  2. P2 — Surface last-sync timestamp: Display qa-index.json updated_at in platform.html Artifacts tab. One-liner change, immediate trust signal.
  3. P3 — Update SKILL.md: After the script exists, update tourney-review SKILL.md Steps 8–11 to just say "run node scripts/gen-qa-index.js" instead of manual JSON edits. AI agents become consumers of the script, not manual editors of JSON.
A
Not Recommended
Option A — GitHub API at Runtime
platform.html calls GitHub Contents API to list *.html files in the repo, then fetches and parses each to build the artifact list dynamically. No qa-index.json needed.
Why rejected: Requires a GitHub personal access token — either exposed in client-side JS (security risk) or proxied via Edge Function (adds infrastructure). GitHub API rate limits (60 req/hr unauthenticated) would break for rapid dev sessions. Also adds ~500ms latency per Artifacts tab load. Overkill for a single-operator platform.
B
Viable But Heavier
Option B — Vercel Edge Function / Build Hook
A Vercel build step or Edge Function scans the repo on each deploy and writes a fresh qa-index.json to the deployment output. Platform fetches it as normal.
Why deferred: Requires adding a build command to vercel.json, installing Node in the build env, and handling Edge Function cold starts. Adds complexity to a currently zero-build deployment. The pre-commit hook achieves the same result with less surface area. Could be revisited if the repo moves to a build pipeline.
C
Recommended
Option C — Build-time Script + Pre-commit Hook
Node.js script scripts/gen-qa-index.js scans all *.html files in repo root, reads <title>, hero eyebrow (axis), hero-sub (desc), hero-meta date, and lifecycle bar state from each file. Generates complete qa-index.json and patches vercel.json rewrites. Registered as a git pre-commit hook so it runs automatically before every push.
Why recommended: Zero runtime cost. No new infrastructure. Works fully offline. Git hook is universal — fires regardless of which agent or human makes the commit. qa-index.json becomes a derived artifact, not a source of truth maintained by hand. Can be run manually anytime with node scripts/gen-qa-index.js.
D
Bonus
Option D — Show Sync Timestamp in Platform UI
Read updated_at from the fetched qa-index.json payload and render it in the Artifacts tab header. One line of JS, no backend changes.
Why include: Closes the feedback loop — Rob can see at a glance whether the index is fresh or stale. Pairs well with Option C since the script will stamp updated_at on every run.

Create scripts/gen-qa-index.js — metadata extraction + qa-index generation
Create C:\Users\Rob\Greenskeeper Studios\01 Repos\TOURney\scripts\gen-qa-index.js.

Script logic:
1. glob('*.html', { cwd: repoRoot }) — find all HTML files in repo root
2. For each file, parse with regex (no DOM needed):
  • <title> tag → extract text after "TOURney — " prefix → ticket title
  • .hero-eyebrow inner text → axis label
  • .hero-sub inner text → summary/desc
  • hero-meta date span → date string
  • .lc-done count → determine lifecycle stage (3 done = review complete, 4 done = executing, 6 done = concluded)
  • MODEL_ID from hero-meta span → author
3. Build entry object: { id, category, stage, title, summary, date, updated, author, url, file, tags, status }
4. Read existing qa-index.json — merge new entries (preserve existing entries that have no matching HTML file, e.g. non-HTML artifacts). Entries with matching HTML files get their metadata refreshed.
5. Sort entries by date descending
6. Write qa-index.json with updated updated_at timestamp

Downstream: Writes qa-index.json → platform.html Artifacts tab reads this
