Schema Design Decisions
  • settings key-value store — settings(tournament_id, key TEXT, value TEXT). 33 named keys in /lib/settings-keys.js const enum (shipped 5-22). Type enforcement is JS-side only — DB accepts any string. No composite index on (tournament_id, key) — admin.html fetches 50+ keys per load via .in('key', [...50 keys...]) with no index to accelerate the lookup.
  • players.team = TEXT — team assignment stored as a plain string on each player row (team TEXT). No FK to any teams table, no enum constraint. Works for the current single-tournament-per-player model. Will need normalization when multi-tournament player profiles become real.
  • tournament_admins email-based — canonical admin model (tournament_admins(tournament_id, email)). Clean. Every RLS subquery does WHERE email = auth.email() — no index on email means a full table scan on every RLS evaluation for every players/settings operation.
  • delete_tournament() manual cascade — stored procedure in 007_round_model.sql deletes: push_subscriptions, scores, trash_talk, tournament_admins, invitations, players, settings, rounds, tournaments. Missing courses and course_holes — added 5-26 in migration 017 but not added to the function. Deleting a tournament leaves orphaned course rows.
  • Dual migration directories — migrations/ (root) = legacy manual applied 001–013. supabase/migrations/ = Supabase CLI format, starts at 000_baseline which snapshots all legacy schema. Forward migrations (013+) go to supabase/ only. Risk: the naming overlap at 013 creates confusion but the 000_baseline makes a fresh CLI apply safe.
Strengths
  • 19 migrations, unambiguous progression (000_baseline + sequential)
  • tournament_admins canonical admin model — is_admin column dropped (mig 006)
  • FK ON DELETE CASCADE on players ↔ tournaments (mig 014)
  • FK ON DELETE CASCADE on courses ↔ tournaments, course_holes ↔ courses (mig 017)
  • Indexes on high-traffic players columns (idx_players_tournament, idx_players_email_tournament)
  • Indexes on scores (idx_scores_tournament, idx_scores_player)
  • /lib/settings-keys.js const enum — 33 typed setting keys, prevents typo drift
  • player_accounts anon read closed (mig 012) — billing data protected
  • push_subscriptions and invitations SELECT locked (mig 013, 015)
Gaps & Bugs
  • [BUG] courses write RLS missing — 20260526000017_courses_course_holes.sql defines only SELECT USING(true). Admin Course tab INSERT/UPDATE will 403 for authenticated users. Upstream: admin.html Course tab writes. Downstream: scorecard yardage reads from course_holes.
  • [BUG] delete_tournament() missing courses/course_holes — stored procedure does not delete from courses or course_holes tables. Tournament delete leaves orphaned rows. Upstream: admin.html "Delete Tournament" action. Downstream: orphaned course_holes on FK-safe course, but course rows remain.
  • [PERF] tournament_admins missing email index — every RLS check on players/settings does SELECT tournament_id FROM tournament_admins WHERE email = auth.email() without an index. Full table scan per policy evaluation.
  • [PERF] settings missing composite index — settings(tournament_id, key) composite index absent. Admin page reads 50+ keys per load — sequential scan on every fetch.
  • [PERF] tournaments missing slug index — tourney-init.js detects slug on every page load. Full scan on tournaments table.
  • [DESIGN] push_subscriptions no UPDATE/DELETE RLS — authenticated users can INSERT (mig 015) but cannot remove stale subscriptions. Subscription cleanup blocked.
  • [DESIGN] mygolf_profiles + donations no migration in scope — tables reportedly added 5-21 but no migration files found in supabase/migrations/ for either. Schema not version-controlled.
§ Plan
Data Model Priorities
Ordered by severity. P1–P2 are live bugs blocking the courses feature shipped today. P3–P5 are performance/governance. P6+ are structural improvements.
P1
Fix courses + course_holes write RLS
Migration 017 defines only SELECT USING(true). Admin Course tab cannot insert/update/delete courses or holes — every write 403s for authenticated users. Ship migration 018 with owner + admin INSERT/UPDATE/DELETE policies.
Impact: Unblocks admin Course tab data entry. scorecard yardage only populates if admin can write holes.
P2
Add courses/course_holes to delete_tournament()
The stored procedure in mig 007 does not know about courses or course_holes. Deleting a tournament leaves orphaned course rows. The FK CASCADE from course_holes → courses is wired, but courses → tournaments is not respected by the RPC.
Impact: Tournament delete is a destructive admin operation — orphaned data is a correctness bug.
P3
Add tournament_admins(email) index
Every RLS policy on players, settings, and rounds evaluates a subquery against tournament_admins.email. Without an index, each policy check does a full table scan. As tournaments and admin counts grow, this compounds per request.
Impact: Reduces RLS overhead on every authenticated DB operation involving players or settings.
P4
Add settings(tournament_id, key) composite index
Admin page reads 50+ settings keys per load using .in('key', [...50 keys...]). Without a composite index the DB scans the full settings table filtered by tournament_id. Add CREATE INDEX idx_settings_tid_key ON settings(tournament_id, key).
Impact: Admin page DB latency reduction. Also helps scorecard and scoreboard which read 5–10 keys per load.
P5
Add tournaments(slug) index + version-control mygolf_profiles/donations migrations
tourney-init.js detects slug on every tournament page load — full scan on tournaments table. Additionally, mygolf_profiles and donations tables have no migration file in supabase/migrations/ — schema not version-controlled, cannot be reproduced from source.
Impact: Slug index: fast tenant detection. Missing migrations: schema governance — blocking for any future fresh-deploy scenario.
P6
Add push_subscriptions UPDATE/DELETE RLS + subscription cleanup
Players can INSERT (mig 015) but cannot remove stale push subscriptions. When a subscription expires or a browser unregisters, the row cannot be cleaned up via the API. Add DELETE policy for own subscriptions.
Impact: Enables subscription lifecycle management. Prevents accumulation of dead push endpoints.

Future
Tournament Teams Table
players.team is a plain TEXT field with no FK, no enum, and no constraint. Works for now but limits queries like "all players on Team A" to string matching. A tournament_teams table with id/name/tournament_id would enable proper relational queries and team-level stats.
Plan: Migration adds tournament_teams table, backfills from settings team_A_name etc., adds FK on players.team_id. Multi-sprint effort — not blocking.
2
Future
Audit Log Table
No audit trail for admin actions — player add/edit/delete, score corrections, round changes. A simple audit_log(tournament_id, actor_email, action, table_name, row_id, old_value, new_value, created_at) table would give full admin accountability. Essential before multi-tenant goes public.
Plan: Trigger-based or application-level insert to audit_log. Start with scores (high dispute risk) then players.
3
Future
Soft Deletes on Players
Players are hard-deleted. Soft deletes (deleted_at TIMESTAMPTZ) would enable "undo remove player" and preserve historical score data integrity. All RLS policies would need a WHERE deleted_at IS NULL filter — manageable addition.
Plan: Migration adds deleted_at column + updates all SELECT policies + application-side filter. Medium complexity.
4
Future
Consolidate Migration Directories
The dual directory situation (migrations/ + supabase/migrations/) creates confusion. The 000_baseline already captures legacy schema. A clean migration doc explaining the history + marking root migrations/ as "applied-only, archived" would eliminate the governance ambiguity.
Plan: Add README to migrations/ marking it archived. All new migrations go to supabase/migrations/ with timestamped prefixes only.
5
Future
updated_at on All Tables
Most tables lack an updated_at column. Difficult to implement cache invalidation, incremental sync, or "last modified" displays without it. Add updated_at TIMESTAMPTZ DEFAULT now() + a trigger to auto-update on row mutation to players, tournaments, settings, rounds.
Plan: One migration, one trigger function, applies to 4–6 tables. Low risk.

SQL to write and apply: 
-- Tournament owner can INSERT/UPDATE/DELETE courses
DROP POLICY IF EXISTS "owner write courses" ON courses;
CREATE POLICY "owner write courses" ON courses
  FOR ALL TO authenticated
  USING (tournament_id IN (
    SELECT id FROM tournaments WHERE owner_email = auth.email()
  ))
  WITH CHECK (tournament_id IN (
    SELECT id FROM tournaments WHERE owner_email = auth.email()
  ));

-- Tournament admin can INSERT/UPDATE/DELETE courses
DROP POLICY IF EXISTS "admin write courses" ON courses;
CREATE POLICY "admin write courses" ON courses
  FOR ALL TO authenticated
  USING (tournament_id IN (
    SELECT tournament_id FROM tournament_admins WHERE email = auth.email()
  ))
  WITH CHECK (tournament_id IN (
    SELECT tournament_id FROM tournament_admins WHERE email = auth.email()
  ));

-- Owner/admin write course_holes (via course ownership)
DROP POLICY IF EXISTS "owner write course_holes" ON course_holes;
CREATE POLICY "owner write course_holes" ON course_holes
  FOR ALL TO authenticated
  USING (course_id IN (
    SELECT c.id FROM courses c
    JOIN tournaments t ON t.id = c.tournament_id
    WHERE t.owner_email = auth.email()
  ))
  WITH CHECK (course_id IN (
    SELECT c.id FROM courses c
    JOIN tournaments t ON t.id = c.tournament_id
    WHERE t.owner_email = auth.email()
  ));

DROP POLICY IF EXISTS "admin write course_holes" ON course_holes;
CREATE POLICY "admin write course_holes" ON course_holes
  FOR ALL TO authenticated
  USING (course_id IN (
    SELECT c.id FROM courses c
    WHERE c.tournament_id IN (
      SELECT tournament_id FROM tournament_admins WHERE email = auth.email()
    )
  ))
  WITH CHECK (course_id IN (
    SELECT c.id FROM courses c
    WHERE c.tournament_id IN (
      SELECT tournament_id FROM tournament_admins WHERE email = auth.email()
    )
  ));

SQL to write and apply: 
CREATE OR REPLACE FUNCTION delete_tournament(p_id uuid)
RETURNS void LANGUAGE plpgsql SECURITY DEFINER AS $$
BEGIN
  DELETE FROM push_subscriptions  WHERE tournament_id = p_id;
  DELETE FROM scores               WHERE tournament_id = p_id;
  DELETE FROM trash_talk           WHERE tournament_id = p_id;
  DELETE FROM tournament_admins    WHERE tournament_id = p_id;
  DELETE FROM invitations          WHERE tournament_id = p_id;
  DELETE FROM players              WHERE tournament_id = p_id;
  DELETE FROM settings             WHERE tournament_id = p_id;
  DELETE FROM rounds               WHERE tournament_id = p_id;
  -- course_holes cascade-deletes when courses deleted (FK ON DELETE CASCADE)
  DELETE FROM courses              WHERE tournament_id = p_id;
  DELETE FROM mygolf_profiles      WHERE tournament_id = p_id;
  DELETE FROM donations            WHERE tournament_id = p_id;
  DELETE FROM tournaments          WHERE id = p_id;
END;
$$;
Note: mygolf_profiles and donations included here preemptively — verify column names match actual schema before applying.
