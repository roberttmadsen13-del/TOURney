Design System
Token Usage & Consistency
✅ CSS Token Usage — Strong

All key pages use var(--gold), var(--bg), var(--card), var(--border), var(--muted) consistently. Top users: admin.html (224 uses), platform.html (197), scoreboard.html (75), marketing.html (73), scorecard.html (66).

Hardcoded rgba(192,144,48,...) creeps into inline styles on marketing.html and home.html — minor, but should be consolidated to tokens.

⚠️ Two Visual Themes — Intentional But Undocumented

home.html (Bova tenant): Playfair Display serif, cream palette, full-bleed hero photography, dramatic scroll animations — theatrical and premium.

Platform pages: Barlow Condensed, dark system, compact cards — operational and dense.

Bifurcation is correct (tenant vs platform), but no design doc exists. New contributors will be confused.

✅ Component Patterns Consistent

Button hierarchy (gold primary / ghost outline), pill badges, card containers, toast notifications, and form group (.fg label + input) are consistent across scorecard, login, player, create, admin.

❌ No prefers-reduced-motion Support

home.html has rich scroll animations (.will-animate with fadeUp + translateY transitions, parallax hero, staggered day blocks). No @media (prefers-reduced-motion: reduce) guard. Vestibular disorder users get no opt-out.

FixAdd @media (prefers-reduced-motion: reduce) { .will-animate { transition: none; opacity: 1; transform: none; } } to home.html.
Per-Page Audit
Key Pages
Critical scorecard.html — user-scalable=no
scorecard.html meta viewport: user-scalable=no. Prevents pinch-zoom on mobile. Accessibility violation — users with low vision cannot zoom to read scores or par values. WCAG 1.4.4 failure.
Fix (scorecard.html:4)Remove user-scalable=no from the viewport meta. Inputs already use font-size:1rem so iOS auto-zoom won't trigger on focus.
High login.html — Raw Supabase Errors Exposed
err.textContent = error?.message passes raw Supabase/GoTrue error strings directly to the user. Can surface internal service names, email enumeration hints ("Email not confirmed"), or confusing technical messages.
Fix (login.html:doSignIn)Map known error codes to friendly messages. Fallback: "Sign in failed — check your email and password." Never show raw error.message from auth providers.
Good login.html — Auth UX Solid
3-mode flow (sign-in / sign-up / forgot) on single card. Button feedback ("Signing in...") during async. Inline error display (.login-err) clears on mode switch. Labels above inputs — not placeholder-only. Focus state uses gold border.
Good player.html — Best-in-class ARIA
Hamburger menu: aria-label="Menu", aria-expanded="false", SVG aria-hidden="true". Drawer: role="menu". Best accessibility implementation in the codebase — use as pattern for other pages.
Good scoreboard.html — Empty State + Toast
Pairs with no scores sorted to end of leaderboard. empty-state div shown when no pairs configured. Trash talk failure shows showToast('Post failed — try again.'). Good patterns — needs replication to other views.
Medium install.html — Orphaned From Player Journey

Good home.html — Motion & Responsive Polished

Mobile & Responsive
Key Findings
✅ Touch Targets Sized Correctly

All form inputs: font-size:1rem (prevents iOS auto-zoom on focus), padding: 0.75rem 0.85rem — well above 44px minimum touch target. Explicitly enforced at 768px breakpoint in home.html.

❌ Scorecard Blocks Zoom (user-scalable=no)

Pinch-to-zoom disabled on the most data-dense mobile screen in the app. Users reading multi-hole scorecards on small phones cannot zoom in. Remove immediately.

✅ Breakpoints Present

home.html: three breakpoints (max-width:480px, 481–768px, max-width:768px). Inputs resized, hero reflows, CTA wraps. scorecard.html and scoreboard.html have at least one mobile breakpoint. marketing.html collapses phone mock at 560px.

⚠️ Table Scroll Not Verified

Scoreboard leaderboard table on narrow screens — overflow scrolling not confirmed. If table clips, scores are cut off on mobile. Needs manual QA on 375px viewport.

Accessibility
A11y Findings
WCAG Fail user-scalable=no on scorecard.html — WCAG 1.4.4
Disabling zoom on a data-entry page fails WCAG 2.1 Success Criterion 1.4.4 (Resize Text). One-line fix.
Missing No aria-live on Dynamic Regions
Leaderboard updates, toast messages, and trash talk posts are injected via JS with no aria-live region. Screen readers miss these updates entirely.
FixAdd aria-live="polite" to toast container and leaderboard list. Add aria-live="assertive" only for critical errors.
Good ARIA on player.html Hamburger — Best in Codebase
aria-label="Menu", aria-expanded="false" (toggled on open), SVG icon aria-hidden="true", drawer role="menu". Template for all other nav hamburgers.
Good Form Labels Explicit
login.html, scorecard.html, create.html all use visible text labels above inputs (not placeholder-only). .fg label pattern consistent. Gold focus ring on inputs.
Unknown Color Contrast Not Verified
--gold: #c09030 on dark --bg: #0d0a05. Estimated contrast ~4.5:1 — borderline AA for normal text. Muted text (--muted: #7a6a54 on dark bg) likely fails AA. Needs Lighthouse or axe audit to confirm.
