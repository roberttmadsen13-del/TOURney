What TOURney Is

Multi-tenant golf tournament SaaS PWA. Deployed at tourney.greenskeeper.studio. Tournament owners create events via a 5-step wizard at /create; players register, score, trash-talk, and install the PWA. Each tenant gets a subdomain or /t/{slug}/ path with brand-injected colors and logo. Platform is static HTML + Supabase (Auth, DB, Edge Functions, Realtime) + Vercel. One active tenant: Bova Invitational (bova.greenskeeper.studio). Registration locked (reg_open=false) pending LLC formation and Stripe live-mode.

Gaps & Real Bugs
  • NEW BUG Duplicate migration prefix 006. migrations/006_drop_is_admin.sql and migrations/006_multi_tourney_players.sql both exist with prefix 006. Supabase CLI applies migrations by filename — alpha sort means drop_is_admin runs before multi_tourney_players, but this is fragile and will confuse any fresh schema apply, CI baseline check, or ops team member. Risk: silent ordering assumptions silently break on a new environment.
  • HIGH player_accounts anon read USING(true). migrations/005: CREATE POLICY "anon read player_accounts" ON player_accounts FOR SELECT TO anon USING (true). Migration 008 fixed the UPDATE path but left SELECT open. Any anonymous visitor can enumerate all player emails, plans (free/player/pro), and billing_status. This is a privacy exposure — billing data should not be publicly readable.
  • HIGH CSP unsafe-inline open. vercel.json HTML Content-Security-Policy includes script-src 'self' 'unsafe-inline'. All pages have substantial inline <script> blocks. This nullifies XSS protection that CSP is supposed to provide. Blocking path: extract inline scripts to .js files.
  • MANUAL SEND_INSTALL_EMAIL_SECRET not set. send-install-email edge function deployed (v4) but webhook header is not yet configured. Rob must set env var in Supabase dashboard and update DB webhook header. Install emails not firing.
  • MANUAL deploy-functions CI secrets missing. .github/workflows/deploy-functions.yml requires SUPABASE_ACCESS_TOKEN and SUPABASE_PROJECT_REF repo secrets. Not yet set — edge functions deploy manually only.
  • BLOCKER Business: LLC not formed → Stripe test-mode only. reg_open=false. Revenue path entirely blocked. No LLC = no Stripe live mode, no Mercury bank, no paid signups.
  • LOW No loading skeletons. Pages blank-flash while Supabase fetches data. Affects scoreboard, feed, directory, profile, champions. UX regression vs native-app competitors.
  • LOW No performance monitoring. No Sentry, no Lighthouse CI, no Core Web Vitals tracking. Performance grade held at B with no regression signal.
  • LOW settings store un-typed. Key-value store flexible but no schema enforcement. Wrong key typos fail silently. Typed settings object or Zod validation would close this.

-- Migration 012: Restrict player_accounts anon SELECT.
-- Bug: migration 005 left "anon read player_accounts" USING(true),
--   exposing email, plan, and billing_status to all anonymous visitors.
-- Fix: drop anon policy, replace with owner-scoped authenticated read.
BEGIN;
DROP POLICY IF EXISTS "anon read player_accounts" ON player_accounts;
CREATE POLICY "auth read own player_account" ON player_accounts
  FOR SELECT TO authenticated
  USING (email = auth.email());
COMMIT;
