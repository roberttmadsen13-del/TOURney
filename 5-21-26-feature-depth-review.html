Critical Gaps
CRITICAL
home.html #format section reads from wrong data source — always shows defaults
Admin saves round formats to the rounds table (format_front, format_back columns) via saveFormats(). home.html reads formats from the settings table using keys format_day1_front, format_day1_back, etc. (home.html:L845). These are completely decoupled data sources. No code writes format_dayN_front/back to settings. The #format section therefore always falls back to hardcoded defaults: Day 1 = Stroke, Day 2 = Scramble/Shambles, Day 3 = Best Ball/Stroke (home.html:L515–L519 DEFAULT_FORMATS). Any format change in admin is invisible on the homepage.
Fix Option A (preferred): in home.html init(), fetch rounds.format_front/back from Supabase (same query as scoreboard.html:L532) and populate the format items. Option B: in admin's saveFormats(), dual-write to settings with keys format_dayN_front/back. Option A is cleaner — single source of truth in rounds table.
CRITICAL
scoreboard.html never fetches yardage — admin-set yards are silently dropped
Admin Course Details saves per-hole yardage to settings.yards_dayN (admin.html saveCourseNameAndPars()). scorecard.html fetches these at init (scorecard.html:L553-L594) and shows them inline per hole. scoreboard.html init() (L528-L534) fetches pars_day% but NOT yards_day%. The Scorecard tab on the leaderboard renders par per hole in .hole-cell.par cells (scoreboard.html:L123) but there is no yardage row at all. Every yard entered in admin vanishes — players reviewing the leaderboard scorecard tab cannot see hole distances.
Fix In scoreboard.html init(): add sb.from('settings').select('*').eq('tournament_id', tournament.id).like('key','yards_day%') to the Promise.all. Store in courseYards. In the scorecard tab renderer, add a yard row between the hole-number header and par row (same pattern as scorecard.html's .hole-yd-inline).
High Gaps
HIGH
home.html:L680 footer hardcodes "The Bova Invitational" — tenant leak
home.html:L680: <div class="footer-wordmark">The Bova <em>Invitational</em></div> — raw tenant-specific copy baked into HTML. tourney-init.js replaces .footer-wordmark with the tournament name, so it works when JS succeeds. But any new tenant on a slow connection, PWA cache hit of old HTML, or JS error shows "The Bova Invitational" in their tournament footer.
Fix Change L680 default text to a generic fallback: <div class="footer-wordmark">TOURney</div>. tourney-init.js already replaces this on load — the default just needs to be tenant-neutral.
HIGH
home.html:L446 hero-meta default HTML is Bova-specific copy
home.html:L446: <div class="hero-meta">3 Days &nbsp;&middot;&nbsp; 2 Teams &nbsp;&middot;&nbsp; 54 Holes...</div> — this is pre-rendered Bova copy. It is overridden by the homepage_details setting when set. Any new tenant who hasn't configured homepage_details sees Bova's event details ("3 Days · 2 Teams · 54 Holes") in their hero until they set that key. The Design tab admin form has the input but there's no onboarding prompt to fill it.
Fix Replace L446 default with generic copy: "Tournament details coming soon" or leave blank. The setting override already works — just neutralize the default.
HIGH
Admin Design tab: hero_photo_url, about_photo_url, color_primary — all saved but not wired to home.html
admin.html:L44 comment explicitly lists these keys as "Pending wire-up in index.html": hero_photo_url, about_photo_url, color_primary, color_ink, color_bg, tourney_name, tourney_year, tourney_location, hero_cta_primary, and the about_stat_ keys. Admins can set these values (they save to Supabase) but nothing reads them on home.html. The Design tab is a partial stub — ~18 of its 24 settings keys have no consumer.
Fix home.html's loadHomepageContent() already fetches all settings keys into a map. Wire each pending key to its target DOM element. Priority order: tourney_name → .hero-title, hero_photo_url → .hero-img src, color_primary → --gold CSS var, about_photo_url → .about-photo-wrap img src.
Medium Gaps
MED
home.html hero scoreboard uses rough tier handicap, not format-aware scoring
home.html:L1127 defines HANDICAP_STROKES = {scratch:0, eagle:4, birdie:8, bogey:12, pretender:16, hacker:20} and divides evenly across 18 holes (L1141: (HANDICAP_STROKES[player.handicap]||0)/18). This approximation is used for the hero mini-leaderboard. scoreboard.html uses full format-aware scoring (best_ball, stableford, match, scramble — scoreboard.html:L607-L663) with actual coursePars[round]. The two leaderboards can show different standings for the same tournament — home's mini-board is always gross-ish, scoreboard is accurate.
Fix (optional) For casual mode, the approximation is acceptable. For competitive mode, home's hero board should use the same calcPlayerRound() logic as scoreboard. Either extract the function to a shared module, or fetch rounds/formats in home's loadHeroScoreboard() and apply the same format logic.
MED
No "Scoring is Open" CTA on home when a round is active
When rounds.status = 'open', home.html shows the hero scoreboard section but has no banner or prominent call-to-action directing players to /scorecard. Players must discover the scorecard via the nav link. Competitor app (Unknown Golf) has a "Resume scoring" deep-link CTA as the primary player action. This is a player experience gap — players don't know scoring is open without hunting the nav.
Fix In home.html's loadHeroScoreboard(), when an open round is detected, inject a gold banner above the hero scoreboard: "Day N scoring is open — Enter your scores →". Mirrors the scoreboard.html nav "Enter Scores" button pattern.
MED
homepage_format_note DOM target unverified — may silently drop value
admin.html DS_FIELD_MAP maps homepage_format_note → lpFormatNote. home.html's format section renders format items from format_day${i}_front/back keys (already broken, see Gap 1) and has a .format-note CSS class in the HTML (home.html:L134 style block). Whether a DOM element with id lpFormatNote or class format-note is populated from the setting is unverified — no code path was found setting this element's content.
Fix Search home.html for lpFormatNote or format-note DOM writes. If missing, add a wire-up in loadHomepageContent(): const el = document.querySelector('.format-note'); if (el && map.homepage_format_note) el.innerHTML = esc(map.homepage_format_note);
Info / Low Priority
INFO
Tee selection (rating/slope) not player-facing on scorecard
Admin can assign a course + tee box to each round (rounds.course_id + rounds.tee_name). scorecard.html auto-loads the linked course's tees and defaults to White tees (scorecard.html:L601-L603). Players cannot change their tee during scoring. Competitor Unknown Golf shows tee selector with rating/slope per hole. This is a competitor gap but low priority for private invitational format (host picks tees for everyone).
INFO
Admin score-edit UI still missing — only players can submit scores
Known gap from prior reviews. Admin has no UI to directly edit submitted scores (e.g., correct a wrong entry). Scores can only be submitted via scorecard.html player flow. Admin can delete tournament entirely (delete_tournament function) but not correct individual score rows.

Forward-Looking Ideas
1
Data Integrity
Settings type schema
The settings table is a key-value store with no type enforcement. A JSON schema or TypeScript type map would catch mismatches (e.g., yards stored as string vs array) before they cause runtime bugs like the format source gap.
Plan: Add a lib/settings-schema.ts with all 40+ known keys, their types, and which pages read them. Validate on save in admin.
2
Player Experience
Admin score correction UI
Admins have no way to fix a wrong score. A simple edit-score modal in admin's player table (click player → edit scores by hole by round) would close the biggest workflow gap for tournament day operations.
Plan: Admin Players tab → row expand → score grid per round, editable inputs, upsert scores on change.
3
Cross-page Consistency
Shared scoring module
home.html, scorecard.html, and scoreboard.html all duplicate scoring logic (DEFAULT_PARS, DEFAULT_FORMATS, format helpers). A single lib/scoring.js would eliminate the divergence that caused the handicap approximation gap on home.
Plan: Extract calcPlayerRound(), stablefordPoints(), getHoleFormat() to lib/scoring.js. Import in all three pages.
4
Player UX
Player tee selection on scorecard
Players currently score against whatever tee the admin linked. A pre-round tee selector (Show available tees → pick one → load yardage) would let mixed-ability groups track accurate distances and improve handicap accuracy for competitive mode.
Plan: scorecard.html setup screen → tee dropdown from golf_courses.tees[] — already loaded, just expose the selector UI.
5
Admin DX
Design tab live preview
Admin Design tab saves 24 settings keys but organizers have no way to preview how their changes look on home.html without opening a new tab. An embedded iframe preview panel in the Design tab would dramatically reduce configuration iteration time.
Plan: Admin Design tab → split-pane layout, right panel = iframe of /t/{slug}/, postMessage updates on each setting change.
