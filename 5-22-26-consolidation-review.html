Fix _parseMentions XSS — feed.html:377
Open feed.html. Find _parseMentions function (near line 377). Currently returns an HTML string built from p.message (raw user input) and assigns the result to innerHTML.

Fix: call esc() on the raw text before constructing mention spans. Pattern: 
function _parseMentions(text) {
  const safe = esc(text);
  return safe.replace(/@(\w+)/g, '<span class="mention">@$1</span>');
}
Verify esc() is available in scope at line 377. If not, it is defined earlier in feed.html — move or re-reference as needed. Do NOT change the innerHTML assignment pattern; only sanitize the input.
Upstream: feed.html reads messages from Supabase posts table. Any authenticated user can post arbitrary text. Downstream: All players viewing the public feed see the rendered output. Risk if wrong: If esc() double-escapes existing &amp; entities, mentions like @name will render broken. Test with a message containing both <script> and @mention text.
Verify Post a feed message containing <img src=x onerror=alert(1)>. Confirm it renders as literal text, not executed. Post a normal message with @mention — confirm mention span still renders with gold styling. Zero console errors.

Part B — Dynamic injection in tourney-init.js:
After window.TOURNAMENT is set and settings map is built, inject: 
try {
  const setMeta = (prop, val) => {
    let el = document.querySelector(`meta[property="${prop}"],meta[name="${prop}"]`);
    if (!el) { el = document.createElement('meta'); el.setAttribute(prop.startsWith('og:') || prop.startsWith('twitter:') ? (prop.startsWith('twitter:') ? 'name' : 'property') : 'name', prop); document.head.appendChild(el); }
    el.setAttribute('content', val);
  };
  setMeta('og:title', window.TOURNAMENT.name + ' — TOURney');
  if (settingsMap.homepage_subtitle) setMeta('og:description', settingsMap.homepage_subtitle);
  if (window.TOURNAMENT.logo_url) setMeta('og:image', window.TOURNAMENT.logo_url);
} catch(e) {}
