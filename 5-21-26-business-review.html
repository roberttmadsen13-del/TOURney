Account Architecture — The Core Blocker

Current state: two disconnected tables. player_accounts (migration 005) stores billing_status, billing_expires_at, billing_ref, and Supabase auth UID. players (migration 001) is per-tournament roster with has_account loose-link field. These are not joined in any query.

The login gate bug (login.html:232-239): player must already exist in players table for the tournament BEFORE auth signup is allowed. This is a fundamental conflict with MyGolf unification — a universal free profile cannot be gated by roster membership.

MyGolf goal: one login works across all tournaments. Profile is free. mygolf_profiles table replaces player_accounts as the universal identity layer. players becomes a tournament-enrollment join record that references mygolf_profiles.

Upstream: Supabase auth → player_accounts → login.html gate
Downstream: player.html billing reads, home.html RSVP pre-fill, scoreboard.html player identity, all RLS policies using auth.uid()
Risk if wrong: all pages reading player_accounts break; existing Bova players lose auth access

Cost per player (infrastructure only):

  • DB rows per player: ~25–50 (player record + scores per round + settings reads). At Pro: ~$0.001/player in storage.
  • Bandwidth per player per tournament: ~0.5MB (RSVP, realtime score updates, page loads). At Pro 250GB/mo: ~$0.005/player.
  • Realtime connections: 1 open websocket per active viewer. No per-player charge on Supabase.
  • Total infra cost per player: <$0.01. Negligible at any realistic tournament size.

Cost per round (infrastructure only):

  • Score rows per round: 1 per player per hole = 18 rows/player/round. 24-player tournament = 432 rows/round.
  • Realtime events per round: ~1 per score entry × 24 players × 18 holes = ~432 DB change events broadcast.
  • Additional bandwidth per round: ~1–2MB total (score fetches, realtime payloads).
  • Total infra cost per round: ~$0.01–0.05. Adding rounds is nearly free.

Cost per team (infrastructure only):

  • Teams are logical groupings — no separate DB table, no additional storage. Cost = player count × per-player cost.
  • 4-player team: ~$0.04 infra. 2-player pair: ~$0.02 infra. Individual: ~$0.01 infra.
  • Teams add zero marginal infra cost beyond their player count.

Derived pricing (cost-up, undercut strategy):

Based on $0.10–$1.00 true cost and competitor floor at $49 (TourneyMaster), TOURney can profitably price at:

  • 1–12 players, 1–2 rounds: $14 — undercuts TourneyMaster entry by 70%. Stripe nets ~$13.27.
  • 13–24 players, up to 3 rounds: $29 — undercuts TourneyMaster by 40–80%. Stripe nets ~$27.86.
  • 25–48 players, up to 4 rounds: $59 — undercuts TourneyMaster by 60%. Stripe nets ~$56.99.
  • 49–96 players, unlimited rounds: $99 — undercuts Golf Genius by 70%. Stripe nets ~$95.91.
  • Round multiplier: ×1.0 base · ×1.15 for 3–4 rounds · ×1.30 for 5+ rounds. Rounds are cheap to host — multiplier is margin capture, not cost coverage.

At 20 tournaments/month blended ~$40 avg: $800/mo gross · ~$760/mo net after Stripe · ~$735/mo net after infra. Breakeven at ~1 tournament/month.

Registration Flow — Current vs Target

Current (home.html RSVP form): 10 manually-entered fields — first_name, last_name, email, phone, handicap, why_me, trash_talk, hat, available_dates, tournament_id. Zero auto-fill. Player must exist in players table first (admin must pre-add). Friction is high.

Target (MyGolf flow): Admin drops tournament home URL. Player clicks Register. If logged into MyGolf: first_name, last_name, email, phone, handicap auto-populate from mygolf_profiles. Player only edits tournament-specific fields: hat, why_me, available_dates. If no MyGolf account: inline creation modal (no redirect to login.html).

Upstream: mygolf_profiles → RSVP pre-fill → players insert
Downstream: scoreboard.html reads players.first_name/last_name, scorecard.html reads players.handicap, player.html reads players.hat
Risk if wrong: name/handicap mismatch between profile and tournament record; duplicate player rows if account-linking fails
