Core Opponent Philosophy (Anti-Cheat)

Every TOURney round must have at least one opponent per competing party. Solo score entry without an opponent is architecturally forbidden — unverifiable scores are the foundation of cheating. This constraint must be enforced at the UI level in create.html and admin.html for every format, every structure. Wolf (4-player minimum), match play (requires paired opponents), and all pair/team formats naturally satisfy this. Individual stroke play must enforce minimum 2 registered players before scoring opens.

Scorecard hooks (scorecard.html:977–981): PAIR_TEAM_FMTS = ['scramble','superball','alt_shot','chapman','greensomes'] drives shared-ball UI. isBestBallHole, isStablefordHole, isMatchHole handle their modes. Pairs hides format section entirely
create.html:611–612 — when structure is pairs, both fmtLabel and fmtSection are hidden with display:none. Pairs-specific formats (alt_shot, greensomes, chapman) are exactly the formats pairs players need. Pairs tournaments are created with default stroke play with no way to change it.
Fix: Remove the hide logic. Instead filter FMT array by structures metadata when pairs is selected.
High
Nassau & Skins have zero scorecard logic
scorecard.html:977–981 — nassau and skins are not in any format hook array. Both silently fall through as stroke play. A player picking "Skins" gets identical scorecard behavior to "Stroke Play" — no side-pot tracking, no skin carryover. The format label displays but the scoring does nothing different.
Fix: Implement overlay scoring UI for both. Nassau needs front/back/total match tracking. Skins needs per-hole carryover display. Both can run on top of any base format.
Structural Gaps
  • No format-structure gating — alt_shot (pairs only) is selectable for an 8-team tournament. wolf requires exactly 4 players but nothing enforces this. Every format is equally available for every structure.
  • No opponent enforcement gate — scoring can be opened for a tournament with 1 registered player. Core anti-cheat principle is not enforced in code.
  • Shambles inconsistency — scoreboard.html:613 includes shambles in PAIR_STROKE_FMTS for aggregation but scorecard.html:977 does not include it in PAIR_TEAM_FMTS. This is intentional (shambles = individual from best drive) but undocumented and confusing for future development.
  • rounds table unvalidated — format_front and format_back are free-text columns (migration 007). No DB constraint validates against known format values. A typo in admin.html silently saves an unknown format.
  • 14 formats missing entirely — Texas Scramble, Florida Scramble, Ambrose, Quota, BBB, Wolf, Snake, Vegas, Waltz, Peoria, Callaway, Bogey/Par, Four-Ball Match, Eclectic.

Architecture
FORMAT_META — Single Source of Truth
Create a shared lib/formats.js (or inline constant) that is the single authoritative list of all formats. Each entry: { value, label, desc, structures[], behavior, overlay, minParty, requiresExactPlayers }. Every file — create.html, admin.html, scorecard.html, scoreboard.html, platform.html — imports or copies from this spec. Kills the current drift where scorecard and scoreboard have slightly different PAIR_TEAM_FMTS arrays.
Build: Add lib/formats.js. Update all consumers. Add Vercel rewrite if needed.
2
Anti-Cheat
Opponent Gate — Core Constraint
Every format requires opponents. Individual stroke: minimum 2 players. Match play: paired brackets required. Wolf: exactly 4. Pairs: minimum 2 pairs (4 players). Teams: minimum 2 teams. The "Open Scoring" button in admin.html reads player count from DB and shows a warning modal if the constraint isn't met. The constraint is never silently ignored — always surfaced to the admin with a clear explanation.
Build: Add validateOpponentConstraint(format, structure, playerCount) helper. Wire to admin "Open Scoring" click.
3
Overlay Formats
Nassau + Skins as True Overlays
Nassau and Skins are not standalone formats — they're side bets layered on top of a base format. The picker should let admins choose a base format plus optional overlays. Skins overlay: real-time carryover counter per hole in scorecard, skin winners displayed on scoreboard. Nassau overlay: front 9 / back 9 / 18-hole match tracking alongside the main score. Stored as overlay_formats: ["skins"] in settings.
Build: Add overlay picker in create.html + admin.html. Add overlay scoring UI to scorecard.html sidebar.
4
Competitive Depth
Wolf — The Premium Format
Wolf is the most sophisticated individual format in the game. Each hole, one player is the "wolf" (rotating). After each tee shot, the wolf can claim that player as their partner. After all 4 tee off, if unclaimed, wolf plays solo 1v3 for double points. Needs: per-hole wolf designation, partner selection UI in scorecard, running point totals per player. This is a premium feature — no other tournament app does Wolf well.
Build: Wolf scoring mode in scorecard.html. Enforce 4-player constraint at tournament creation.
5
Differentiation
Format Library as a Market Position
No tournament platform covers all ~27 formats with real scoring logic. GHIN covers stroke. GolfGenius covers some team formats. Tourney covering the full world of formats — with structure gating, real-time scoring, and mobile-first UX — is a genuine competitive moat. Every format added is one more reason a tournament organizer chooses Tourney over building a spreadsheet or paying for enterprise software.
Build: Ship all formats. Add "Format Explorer" page. Use as a marketing hook on landing page.

Add Wolf format with dedicated per-hole scoring UI
Wolf requires a fully custom scoring path — the most complex format in the list:
  • At tournament creation: Wolf only available for Individual structure. Enforce playerCount === 4 — show warning at create time and hard-block scoring if violated.
  • Wolf rotation: player order is fixed (typically by tee time / draw). On each hole, the wolf is the last to tee off in rotation (hole 1: player 4 is wolf, hole 2: player 3, etc.). Display wolf designation on scorecard.
  • After each tee shot (holes 1–3), wolf can tap "Choose Partner" next to any of the first 3 players. If they choose before the 4th tees off, it's a 2v2. If they wait until all 4 have hit, they can pick any partner. If they go it alone (no partner), they play 1v3 for 2× points.
  • Hole scoring: if wolf team wins the hole, wolf+partner each earn 1 point (or 2 if solo). If non-wolf team wins, they each earn 1 point (or 2 if wolf was solo). Tie = carry.
  • After 18: final points totaled. Scoreboard shows Wolf points per player.
  • Add wolf_state to scorecard local state: { rotation: [p1,p2,p3,p4], holeWolf: {}, holePartner: {}, holePoints: {} }. Persist to scores table as metadata.
