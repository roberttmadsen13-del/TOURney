§6 — Escalation
When Something Looks Off
Triage in this order. Stop at the first one that explains the symptom.
Symptom: Anthropic spend not dropping after 1 week
  1. Anthropic Console → Usage → verify cache_read_input_tokens climbing on multi-turn sessions. If still 0, cache breakpoint wrong — see step 3 rollback.
  2. Check status line shows Sonnet 4.6 by default. If Opus, settings.json didn't reload — restart Claude Code.
  3. /context-mode:ctx-stats — if savings ratio < 40%, habits not sticking. Audit recent Read calls.
Symptom: Output feels weaker than before
  1. Identify the task class (review? plan? security?). If security or audit, that skill should be on Opus — check its SKILL.md frontmatter.
  2. Re-run that one task with /model opus. If output materially better, log task type and consider promoting that skill back to Opus.
  3. If complex task on default Sonnet feels shallow, retry with /effort xhigh for that turn.
Symptom: Cache misses on every turn
  1. Confirm prefix is genuinely static — no timestamps, no per-turn tool definitions, no rotating session ID before the breakpoint.
  2. Shrink the cached block to just CLAUDE.md alone. Re-test. If hits resume, add files back one at a time until the miss returns.
  3. Check 5-min TTL — if sessions span longer idle gaps, hits will look sporadic. That's expected, not broken.
Last resort
  • Full rollback (§5) takes 5 min and restores pre-runbook state exactly. No data loss possible — all changes are local config.
  • Re-read source plan: 5-7-26 token savings plan — risk register pre-mortems every failure mode here.
