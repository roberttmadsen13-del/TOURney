What "Format Scope" Means

The DB stores format_front and format_back per round. Most formats are pure-9 (stroke, scramble, best ball) — mixing them per nine is fine. But three classes are structurally broken when split:

  • Whole-round formats — math spans 18 holes: nassau (front 9 + back 9 + 18 segments), match (running 1-up/2-up), four_ball_match, wolf (rotating wolf per hole), bogey_par (running net vs par), skins (carryover ties), quota (36-hcp target).
  • Whole-tourney formats — aggregate across all rounds: eclectic (best score per hole across the tourney), peoria (post-round 6-hole handicap), callaway (post-round handicap from worst holes).
  • Composition-only — Slayer 3v1 is a team split, not a format. Already refactored to settings.team_mode.

Strengths
  • Single source of truth: FORMAT_META consumed by all 4 surfaces.
  • DB schema correct: per-9 split is a column-level decision (format_front / format_back) — easy to lock when needed.
  • Existing overlay and requiresExact props prove the pattern of scope-flagging formats.
  • scoreboard.html:626 already shows the pattern: roundIsMatch = fmts.front===match && fmts.back===match. Bake into all whole-round formats.
  • Slayer 3v1 split out cleanly into settings.team_mode (refactor on this same day) — proves composition can live separately from format.
Gaps / Real Bugs
  • Create lets users pick illegal combos. e.g. Nassau front 9 + Stroke back 9 → Nassau math broken. create.html:713-717 independent selects.
    Upstream: none.
    Downstream: rounds row written with broken pair → admin loads broken pair → scoreboard tries to compute nassau scores → silently wrong leaderboard.
  • Admin re-emits the bug. admin.html:1099-1108 renders identical independent front/back selects with no scope guard.
  • Whole-tourney formats (eclectic/peoria/callaway) selectable per nine. No code prevents a 3-day tourney with eclectic on Day 1 front, stroke on Day 2, callaway on Day 3 back.
  • FORMAT_META lacks a scope property. Existing overlay:true flags 2 formats but doesn't enforce anything; requiresExact:4 only filters by party size.
  • create.html fallback FMT array (lines 348-355) is stale. Missing 13 formats present in FORMAT_META; if formats.js fails to load, user sees a degraded picker.
  • No DB constraint. rounds.format_front + format_back are free-text. Migration 007 has no CHECK; nothing prevents format_front='nassau', format_back='peoria'.
  • scorecard.html:1108-1111 branch only checks fmt (single value) — assumes whole-round format. If front/back split, panel renders for front 9 only, then disappears at hole 10.
  • Format descriptions repeat (bug shown by user 6/1/26). Once fixed (event listener moved to addEventListener on the new fd-{key}-{side} select) — verify on live.
Cross-Page Risk Map

Upstream: create.html step 2 → rounds.format_front / format_back insert. Admin saveFormats() (admin.html:1115) overwrites same columns.

Downstream: scorecard.html reads rounds.format_front + format_back (line 583, 614) and renders the format-specific panel at line 1108. scoreboard.html reads same columns (line 536, 550), computes roundIsStableford / roundIsMatch (line 626), then forks scoring logic. home.html reads format names for the landing card. champions.html aggregates final scores per round.

Risk if scope not enforced: any illegal combo silently corrupts the leaderboard, since each surface independently coerces unknown combos to behavior:'default' (stroke aggregate). Player enters strokes thinking it's match play, scoreboard shows stroke totals.

§ Plan
Lock Format Scope, End to End

Add a lockScope property to FORMAT_META. Then enforce it in every surface that reads or writes a format — create, admin, scorecard, scoreboard, DB.

Strategic Priorities (P1 → P5)
  1. P1 — Add lockScope to FORMAT_META. Values: 'nine' (default, mix freely), 'round' (locks both nines), 'tourney' (locks every round + both nines).
  2. P2 — Enforce in /create. If user picks a round format on front 9, mirror to back 9, gray out back. If picks a tourney format on any select, mirror to every round + both nines, gray all others.
  3. P3 — Enforce in admin. Same logic in admin.html format editor. Plus: warn if existing DB row has an illegal combo (migrated tourneys).
  4. P4 — Defensive read in scorecard + scoreboard. If format_front !== format_back for a round-scope format, coerce to format_front (single source of truth), log a console warning.
  5. P5 — DB CHECK constraint. Migration to add a CHECK that enforces scope rules so future writes can't violate.
1
P1 · Foundation
Tag every format with lockScope
Per-format property answers: "can a player split this between front 9 and back 9?" Default 'nine' for stroke / scramble / best ball etc.; 'round' for nassau / match / wolf / skins / quota / bbb / snake / vegas / waltz / bogey_par / four_ball_match; 'tourney' for eclectic / peoria / callaway.
Build: 1 prop addition × 27 entries in lib/formats.js. ~30 LOC.
2
P2 · Create UX
Create flow auto-locks dependent selects
When user picks Nassau on Day 1 Front, Day 1 Back snaps to Nassau and disables. When picks Eclectic on any nine of any day, every other front/back select snaps + disables. Visual: locked select gets a tiny 🔒 hint + opacity 0.55. Unlock by switching the source select back to a per-9 format.
Build: Hook into existing renderFormat + updateFmtDesc. ~50 LOC, no new endpoints.
3
P3 · Admin Edit
Admin enforces same scope
Admin's per-round format edit cards mirror create's logic. When admin loads a tourney with an illegal pre-existing combo (legacy data), show an orange banner "Round 2 has an invalid format split. Click to repair." that resets to format_front for both nines.
Build: Refactor renderFormatEditor (admin.html:1080+). +1 repair button per affected row. ~70 LOC.
4
P4 · Defensive Read
Scorecard + scoreboard coerce illegal combos
Any time scorecard.html or scoreboard.html reads {front, back}: if FORMAT_META[front].lockScope !== 'nine' and front !== back, treat as front for both nines and console.warn('illegal format combo, coerced'). Prevents corrupted-data renders.
Build: Helper normalizeRoundFormats(roundFormats) in lib/formats.js. Called by both pages. ~20 LOC.
5
P5 · DB Constraint
Postgres CHECK to make illegal combos impossible
New migration: CHECK constraint on rounds that asserts: if format_front is in the round-locked list, format_back must equal format_front. Enforces at write time so even a buggy client can't poison the table.
Build: 1 SQL migration. Run on dev branch first, verify no existing rows violate, then promote. ~10 LOC SQL.
Forward — UX Polish

Once scope is locked, format picker can show a small "scope badge" next to each option: [9], [18], [ALL]. Makes the constraint visible before the user clicks. Description text already updates correctly after today's addEventListener fix.
