XSS Surface Fixes
3 surfaces. All fixable in under 2 hours total. No migrations needed.
MEDIUM scoreboard.html â€” _parseMentions(p.message) raw to innerHTML scoreboard.html:1096
p.message is user-submitted trash talk from the DB. It flows into _parseMentions() which applies a regex but does NOT escape the base text first. A player who submits <script>stealCookies()</script> as a message would have it execute in every other player's browser when they view the scoreboard.
Fix â€” 15 minutes 
function _parseMentions(raw) {
  const safe = _esc(raw); // escape FIRST
  return safe.replace(/@([A-Za-z][A-Za-z '.'\-]*[A-Za-z])/g,
    '<span class="mention">@$1</span>');
}
The _esc() helper already exists in scoreboard.html. Also check feed.html for the same parseMentions pattern â€” fix both.
MEDIUM admin.html â€” url variable interpolated into innerHTML admin.html:2044, admin.html:2194
Both sites interpolate a url variable (DB-sourced logo/image URL from settings) directly into an innerHTML template. A javascript: scheme URL injected here would execute on admin load.
Fix â€” 30 minutes Add a safeUrl() helper at the top of admin.html's script block, then wrap both sites: 
function safeUrl(u) {
  try {
    const p = new URL(u);
    return (p.protocol === 'https:' || p.protocol === 'http:') ? u : '';
  } catch { return ''; }
}

// At both innerHTML sites:
// Before: `... src="${url}" ...`
// After:  `... src="${safeUrl(url)}" ...`
MEDIUM â†’ LOW (post-refactor) CSP â€” unsafe-inline makes script CSP useless vercel.json
Current: script-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net. With unsafe-inline, the browser executes any <script> tag including ones injected via XSS. CSP provides zero protection against script injection. Root cause: all JS is inline per-page HTML (no bundler).
Fix â€” 2-day refactor (pre-launch)
  1. Move each page's JS to a companion .js file (e.g. admin.js, scoreboard.js)
  2. Remove 'unsafe-inline' from script-src in vercel.json
  3. Add Cross-Origin-Opener-Policy: same-origin and Cross-Origin-Resource-Policy: same-origin headers
  4. Add report-uri /api/csp-report â€” create a tiny edge function that logs violations to a DB table
Until this refactor ships, the inline XSS fixes (parseMentions + safeUrl) are the primary defense layer.

Business Future-Proofing
Security for Multi-Tenant + Business Launch
When you go from Bova-only to selling to other tournament organizers, these become load-bearing. Plan them now, implement before Phase 2 launch.
Multi-Tenant RLS Isolation

Phase 2 adds multiple tournaments from multiple organizers. Current RLS uses tournament_id filtering but still allows cross-tournament data leakage via open policies. Before Phase 2:

  • All SELECT policies must filter by tournament_id matching the caller's scope
  • Use current_setting('app.tournament_id') or explicit query filters â€” explicit is safer
  • Audit every table: can Organizer A see Organizer B's player list? Right now: possibly yes
Audit Log Table

Before charging money: you need an audit trail. Who changed which score, when. Who created/deleted players. What settings changed and by whom. Required for dispute resolution and fraud investigation.

  • Create audit_log table: id, table_name, row_id, action, actor_email, old_value jsonb, new_value jsonb, created_at
  • Populate via DB triggers on scores, players, settings, tournaments
  • Admin-only read. Never deletable by any client policy
Rate Limiting

Current edge functions have no rate limiting beyond Supabase's platform limits. Once live:

  • send-install-email: max 1 per player per tournament per 24hr (check DB before sending)
  • create-checkout: idempotency key to prevent double-charges
  • Trash talk submit: already rate-limited at DB level (migration 011) â€” verify limit is sane
  • Score submit: once per hole per player per round (UNIQUE constraint already enforced)
Player Data Deletion (GDPR-adjacent)

Even outside EU, good practice and builds trust. Before charging real money:

  • Admin panel: "Delete Player" must cascade-delete scores, invitations, push_subscriptions, player_accounts row
  • Self-serve: player can request account deletion via profile page
  • Supabase Auth user deletion must be paired with player record deletion
  • Retention policy: scores stay for historical records, PII (email, phone) removed
CSP Violation Reporting

After removing unsafe-inline, add a reporting endpoint:

  • Add report-uri /api/csp-report to CSP header in vercel.json
  • Create edge function csp-report: logs violations to csp_violations table
  • Add platform.html widget: show last 10 violations in admin security panel
  • Any violation in production = real attack attempt or misconfiguration, not noise
Security.txt + Disclosure Policy

When serving real tournaments with real money:

  • Add /.well-known/security.txt with contact email + PGP key
  • Add vercel.json rewrite for /security.txt
  • Document: what you'll fix and how fast (24hr critical, 7-day high)
  • Gives researchers a responsible disclosure path â€” prevents public dumps
