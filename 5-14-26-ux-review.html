Design System

Tokens: :root{} block defined per page — 11 tokens (--ink, --gold, --gold-l, --gold-p, --cream, --red, --green, --border, --bg, --card, --muted). Consistent across 25+ pages. Minor drift: nav link colors use raw rgba(240,230,204,0.6) instead of --cream, and admin.html .status-open uses #2a7a20 not --green token.

Typography: 4-font system — Playfair Display (headings/display), Barlow Condensed (nav/buttons/uppercase labels), Barlow (body/UI copy), DM Mono (eyebrows/badges/monospace). Role mapping consistent across all pages. Google Fonts imported per-page via single link tag.

Buttons: Two naming conventions coexist — btn-primary (admin.html, full-width) and btn-gold (marketing.html, inline). Same visual output, different class names. Low risk today, drift risk as pages multiply.

Motion: fadeUp stagger animations on home.html hero (0.25s–0.78s delays). prefers-reduced-motion guard present (10a676f). Skeleton shimmer on scoreboard + home (10a676f). Button transitions at 0.2s.

MEDIUMhome.html ~line 429 — heroLogoImg alt="" (empty)
The hero logo <img id="heroLogoImg"> has an empty alt attribute. Screen readers announce "image" with no description. WCAG 1.1.1 Level A failure. tourney-init.js injects the src but does not set alt dynamically, leaving the empty fallback.
FixSet fallback on element: alt="Tournament logo". In tourney-init.js where heroLogoImg.src is assigned, also set heroLogoImg.alt = (tournament.name || 'Tournament') + ' logo'.
MEDIUMlogin.html — doLogin() has no submit spinner
The sign-in button provides no feedback during Supabase auth. On 3G or slow connections a 1–3 second wait shows zero UI state change — button appears broken. The async function doLogin() awaits but never updates button state on entry.
FixOn function entry: btn.disabled = true; btn.textContent = 'Signing in…'. On error: restore to enabled + original label. On success: leave disabled (redirect unmounts page).
MEDIUMscorecard.html — No loading skeleton on hole grid fetch
scorecard.html is the primary player-facing page on tournament day. During Supabase data fetch the hole grid container is blank — no skeleton, no spinner. Players see an empty scoring grid with no feedback for 1–2 seconds. Deferred as P3 in the May 13 sprint.
FixCopy .skeleton-row + @keyframes shimmer from scoreboard.html (10a676f). Add 18 skeleton rows to the hole grid container. Swap with real rows on data resolve.
LOWhome.html — Zero-player pre-registration empty state missing
When a new tournament has 0 registered players, the players/roster section renders nothing — no message, no guidance. The first player to visit sees a blank section with no CTA.
FixIn the players section JS: if players.length === 0, inject an .empty-state card: "Registration is open — be the first to join!" with a link to the RSVP form.
LOWmanifest.json — Missing apple-touch-icon 180×180
manifest.json declares icon-192.png (any) and icon-512.png (maskable). No 180×180 icon for iOS home screen. Safari crops icon-192.png to 180×180 as fallback — may clip logos with important edge content. Blocked on Rob providing the asset.
Fix (Rob to provide asset first)Add icon-180.png to repo root. Append to manifest.json icons: {"src":"/icon-180.png","sizes":"180x180","type":"image/png","purpose":"any"}. Add <link rel="apple-touch-icon" href="/icon-180.png"> to all HTML <head> blocks.
LOWadmin.html — .status-open uses hardcoded #2a7a20, not --green token
.status-open { color:#2a7a20; border-color:#2a7a20; background:rgba(42,122,32,0.08); } — hardcoded hex bypasses the design token. If --green changes this badge stays stale.
FixReplace #2a7a20 (×2) and rgba(42,122,32,0.08) with var(--green) and rgba(39,174,96,0.08).
FEATUREPlatform Hub — Axis scorecard not driven by grades.json (Rob request)
The platform hub displays axis grades but they are hardcoded HTML. Every review skill already updates grades.json and pushes. The display just needs to read from it dynamically. Rob explicitly requested this: "should be part of the site's code and be automatic."
Fix (P1 — runbook step 1)Add fetchAndRenderGrades() to platform.html. Fetches /grades.json on load, reads axes[key].scores[0].score for each axis, updates DOM cells by data-axis attribute. Zero manual HTML edits needed after future reviews.

Implement axis scorecard auto-update in platform.html
In platform.html: find the axis grade display section (grid of axis score cells showing A/B+/etc.). Add data-axis="architecture" (and matching keys for each axis) attributes to each grade cell if not already present.

Add function before closing </script>:
async function fetchAndRenderGrades() {
  try {
    const r = await fetch('/grades.json'); const d = await r.json();
    for (const [key, axis] of Object.entries(d.axes)) {
      const el = document.querySelector('[data-axis="' + key + '"]');
      if (el && axis.scores && axis.scores[0]) el.textContent = axis.scores[0].score;
    }
  } catch(e) {}
}
document.addEventListener('DOMContentLoaded', fetchAndRenderGrades);
VerifyPush a test grade change to grades.json. Load /platform. Axis score cell updates without touching platform.html HTML. Zero manual edits required after future reviews.
