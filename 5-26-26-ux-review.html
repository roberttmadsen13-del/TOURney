Verdict

Admin works. But "works" is not the bar for a pro SaaS product. The Design tab is a wall of 33+ unorganized inputs with no sections, no save-per-group, and no feedback when settings aren't wired to the homepage. The score table requires manual Refresh instead of auto-loading. Loading states are text-only. Empty states provide zero guidance. Mobile admin — especially score entry and the Design tab — is painful. Access tab has invite-only, no admin revoke. Several settings keys (team_a_color–team_h_color, captains for teams C-H, schedule_json) have no usable UI. Grade: B. Significant UX debt for a paying-customer surface.

Tab 1 — Command Center: Findings
  • Score table requires manual Refresh. Default state: "Select Refresh to load scores." (admin.html:471). On-tab-open auto-load is table stakes for any dashboard.
  • No round open/close status badges. Rounds table shows format but no visual status indicator (open vs. closed vs. not-started). Admin must mentally track which rounds are live.
  • Stats show counts only — no context. "12 players" tells you nothing. "12 / 16 max (2 unassigned)" gives actual signal.
  • Clear Scores is a nuclear option with no confirmation dialog. admin.html:514 shows the destructive clear-scores button. No are-you-sure gate. One misclick wipes a round's scores.
  • No player edit/delete from Command Center. Players table is read-only. If Rob typed a name wrong or needs to remove someone, there's no path — requires Supabase dashboard.
  • Hat orders stat card conditionally hidden (good), but stat grid layout shifts when cards hide — visual jank on load when hat merch is off.
Tab 2 — Design: Findings (Biggest Problem Area)
  • No visual section grouping. 33+ settings keys render as a single continuous form. Brand, Registration config, Team settings, and Schedule are interleaved with no accordion, no card grouping, no visual hierarchy. Scrolling 400px to find "team captain" is a usability failure.
  • One giant save at bottom. Editing brand colors AND team names AND registration toggles triggers one save for everything. Partial saves impossible. No per-section save.
  • No unsaved-changes guard. Editing anything in Design tab then switching to Course tab: all edits silently lost. No beforeunload warning, no "you have unsaved changes" prompt.
  • Color fields (team_a_color–team_h_color, color_primary, color_ink, color_bg) are plain text inputs. Admin must type hex codes from memory. No color picker, no preview swatch. This is 2026.
  • Captain fields only for Team A and "Challengers" (Team B). DS_FIELD_MAP maps team_a_captain and challengers_captain only. Teams C-H have no captain designation path even though up to 8 teams are supported.
  • schedule_json has no structured UI. Raw JSON key exists in DS_ALL_KEYS but no schedule builder. Admin either has no way to set schedule from the UI, or there's a textarea expecting raw JSON — neither is acceptable for a paying customer.
  • Comment says "Pending wire-up in index.html" (admin.html:~2560). Multiple settings written by this tab may not actually render anywhere. Admin edits settings that silently do nothing. No feedback, no preview link, no visual confirmation.
  • Tab label "Design" is misleading. This tab controls Brand, Content, Registration settings, Team config, AND Schedule. "Design" undersells it and makes team-related settings impossible to find intuitively.
  • Logo upload has no dimensions guidance. Admin uploads a file with no hint of recommended size. Oversized images just break the nav.
Tab 3 — Access: Findings
  • No list of current admins. Access tab provides an invite-by-email flow but no display of who is currently an admin on this tournament. You can't see what you've done or who has access.
  • No revoke path. Once invited, an admin can't be removed from the UI. Requires Supabase dashboard. This is a basic security requirement for any multi-admin surface.
  • No role differentiation. All admins have full access (edit settings, manage players, enter scores). No read-only viewer role, no score-entry-only role. Not blocking now but becomes painful as you scale to clients with multiple co-admins.
  • Invite status not shown. After inviting someone, there's no "pending / accepted" status display. Admin doesn't know if the invite worked.
Tab 4 — Course: Findings
  • Per-day accordion is well built — search vs. custom mode toggle, front/back nine inputs, yardage support. Strongest tab on the page.
  • No "copy Day 1 to Day 2 and 3" shortcut. If the same course is used all days (common), admin must re-enter identical data 3 times. A "Copy to all days" button would eliminate this entirely.
  • Course search results have no source attribution. Results come from golf_courses DB. No indication of data freshness or "request a correction" path for bad data.
  • No confirmation after save. After saveCoursePars(), feedback is only a toast. No visible persistent indicator that "Course: Augusta National — saved for Day 1" is set. Next visit: unclear if data persisted.
  • Par input grid wraps to 9 columns at 600px (admin.html CSS: .par-inputs{grid-template-columns:repeat(9,1fr)}). At narrow widths the 9 front + 9 back inputs cramp to ~30px each — usable but barely.
Team Assignment (within Command Center): Findings
  • Chip-click assignment works but has no keyboard path. Mouse/touch only. No keyboard access to assign a player to a team.
  • Auto Balance doesn't explain its algorithm. One click redistributes players silently. No undo. If the balance is wrong, admin must re-drag manually.
  • Team count selector is text buttons — not visually obvious that "2 3 4 5 6 7 8" are selectable modes. No active state ring or clear selection affordance beyond font weight.
  • Unassigned pool label "click to assign" but assignment target is unclear. Which team gets the clicked player? Behavior depends on state. Not self-explanatory.

Mobile / Responsive Audit
  • Score entry table on mobile. Score entry table has no overflow-x:auto wrapper. On a 375px iPhone, 18 columns + player name clips horizontally. Scores entered on-course via mobile are the primary use case — this is a critical gap.
  • Design tab scrolling on mobile. 33+ inputs = ~2000px of vertical scroll. No section anchors or accordion. Mobile admin cannot efficiently manage settings.
  • Tab row on mobile. 5 tabs at padding:0.75rem 1.5rem each = ~7.5rem minimum width per tab. Total tab bar ~400px on a 375px screen. Tabs clip or wrap. No mobile tab solution (swipe, dropdown, etc.).
  • Team assignment on mobile. Chip pool collapses to single column (good), but drag-to-assign may not work correctly on touch devices — no touch event handling observed. Click-to-assign should be verified on iOS/Android.
  • Nav mobile hamburger. nav-mobile.css + nav-mobile.js loaded (good), but admin-specific nav (logout button, Admin badge) may not integrate cleanly with mobile nav overlay.
Accessibility (a11y)
  • Tab list has no ARIA roles. The 5 <button class="admin-tab"> elements function as a tab interface but have no role="tablist", role="tab", or aria-selected attributes. Screen readers see 5 buttons, not a tab navigation.
  • Tab panels not aria-labelled. Tab content <div>s have no role="tabpanel" or aria-labelledby. Hidden panels use display:none (correct) but panel identity is not exposed.
  • Color inputs have no label for blind users. Color picker fields (if implemented as <input type="color">) need accessible labels — team color for what, which team, etc.
  • Toast notifications. Toast feedback (showToast()) is visual-only. No role="alert" or aria-live region. Screen reader users get zero feedback when saves succeed or fail.
  • Stat cards have no semantic structure. Numbers in <span id="sTotal"> etc. with no accessible label connecting the number to its meaning.

Root Cause Identified: Setup vs. Live-Day IA Split

Prior opinions called the Design tab "chaotic" without naming why. The actual root cause: admin's work splits into two distinct mental modes — Setup (pre-tournament: course, teams, branding, schedule, access) and Run-Day (live: score entry, round state, leaderboard). The 5-tab layout mixes both modes into every tab. "Command Center" contains stat cards (run-day) AND team assignment (setup). A product-grade admin would split into a top-level Setup ↔ Live mode or clearly separated nav sections. This is the structural fix every other improvement flows from.

New Findings (not in any prior opinion)
  • "Design" tab label is a category error. The tab controls registration rules, team rosters, captains, schedule, and branding. "Design" signals styling — admins hunting for registration settings will never look here. Rename to "Setup" or "Tournament Settings". Trivial diff, massive orientation win.
  • No "View live site" link adjacent to save. Every setting in Design writes to settings table that renders on the public homepage — but there's zero preview link. Admin saves blind, opens a new tab, hunts the URL, refreshes. This is why "settings silently do nothing" feels true even when wires work. Feedback loop is broken, not the plumbing.
  • No persistent tournament context header. Nothing in the admin chrome tells the admin which tournament they're editing. In a multi-tenant world, opening admin on the wrong subdomain = silently editing the wrong event. Needs tournament name + tenant badge in the sticky nav.
  • Stat cards are dead affordances. sTotal, sTeamA etc. render counts but clicking them does nothing. In every modern SaaS admin (Stripe, Linear, Vercel) stat cards are filter-shortcuts. These look interactive but aren't — false affordance.
  • buildScheduleEditor() already exists. The ticket implies schedule is raw JSON textarea. There IS a structured UI built — the gap is wire-up to the public display, not missing data entry. Ticket framing wrong on this.
  • Course mode (Search/Custom) is per-day, should be tournament-level. setCourseMode('day1','search') — admin running a 3-round one-course event must toggle mode 3 times. Mode should default tournament-level with per-day override.
  • No autosave on single-key toggles. reg_open, notification toggles — these are boolean flips. Requiring Save for a toggle is archaic in 2026. Single-key settings should write immediately on change.
  • No "last saved" timestamp anywhere. Admin can't verify a change persisted across sessions. Silent save + no timestamp = zero trust.
  • celebrationStyle select has no preview. Admins won't know what each style does. Needs inline mini-preview or "Preview" button next to the select.
  • No keyboard shortcuts for score entry. Tab → next hole, Enter → save row. A clubhouse admin entering scores in real-time is entirely mouse-dependent. High-frequency task with zero keyboard optimization.
Disagreements with Accumulated Ticket
  • Custom confirmation modal (Step 3): keep as P2–P3, not P4. Third opinion demoted because confirm() exists. Disagreed — native confirm() is a UX smell in paid SaaS. Looks like 2008, breaks brand trust, can't be styled. For a product charging $14–$99/event, "are you sure?" dialogs should be on-brand. Keep custom modal but scope narrowly: one reusable helper, used everywhere.
  • Step 6 (color pickers) replacement: Don't just strike it — retarget to a WCAG contrast validator between color_primary, color_ink, and color_bg. Admin can pick colors that are unreadable together. A live contrast ratio warning adjacent to the color fields is more valuable than the pickers themselves (which already exist).
  • Mobile tab fix: overflow-x:auto is a band-aid. A 5-tab admin on 375px needs a real mobile pattern — bottom-sheet tab picker, dropdown, or an icon-only collapsed nav — not a scrollable row of text tabs. Scrollable tab bars on mobile violate standard mobile nav conventions (iOS HIG, Material).
