What TOURney Is

Multi-tenant golf tournament SaaS PWA. Organizers create tournaments, invite players, run multi-round scoring across 12 formats (individual stroke, team scramble, pairs, etc.), and manage results via a rich admin panel. Players get realtime scorecard, feed with @mentions, leaderboard, champions archive, and course map. Stripe billing gates the pro tier. One live tenant: Bova Invitational 2026.

§2 — Council of 5

Forward-Looking Ideas

Five strategic improvements. Unchanged from May 13 — none shipped yet. Each carries a concrete build plan.

1
SECURITY
CSP Script Extraction
Every HTML page has substantial inline <script> blocks — that forces unsafe-inline in the CSP. Extracting them to external .js files unlocks a strict script-src 'self', making the _parseMentions and url innerHTML bugs unexploitable at the browser level before code fixes even land. Highest-leverage security move on the board.
Build plan: Extract each page's inline <script> to a paired pagename.js. Replace inline block with <script src="/pagename.js">. Remove 'unsafe-inline' from vercel.json CSP. Refactor any remaining inline event handlers to addEventListener. ~1 day per 3–4 pages, ~4 days total.
2
BUSINESS
Stripe Test-Mode Dry Run
create-checkout and stripe-webhook are both wired and deployed. The missing step before live mode is a full end-to-end test run: card 4242..., checkout session, webhook fires, billing_status updates in DB, player-upgrade page reflects new status. This surfaces config bugs before live money.
Build plan: Set STRIPE_SECRET_KEY to test key in Supabase env. Set STRIPE_WEBHOOK_SECRET to test secret. Use Stripe CLI stripe listen --forward-to to relay test events. Walk /player-upgrade with card 4242 4242 4242 4242. Verify player_accounts.billing_status = 'active'. Test cancellation event path. ~2h.
3
FEATURE
Round Summary Email
send-install-email already handles the email infra. A new send-round-summary edge function sends each player their round scorecard + leaderboard position after the admin marks a round complete. High engagement touchpoint, low build cost because the plumbing is there.
Build plan: New edge function send-round-summary/index.ts. Trigger: admin.html round-complete button. Fetch player scores + leaderboard position for that round. Email template: scorecard summary + position + "View full leaderboard" CTA. Gate on billing_status (pro tier). ~4h.
4
DEVOPS
GH Actions CI/CD
Zero CI exists — every push deploys to prod via Vercel with no checks. A minimal GitHub Actions workflow adds lint + edge-function type-check on every PR, and automates the manual supabase functions deploy step on merge. Prevents broken-function incidents.
Build plan: .github/workflows/ci.yml — on PR: ESLint + Deno type-check on supabase/functions. .github/workflows/deploy-functions.yml — on merge to main: supabase functions deploy --all using SUPABASE_ACCESS_TOKEN secret. Add secret to GitHub repo. ~3h.
5
LEGAL
ToS + Privacy Pages
Required for PSP onboarding, LLC credibility, and Stripe activation. Two static HTML pages. Copy can start as standard SaaS boilerplate (Termly, Docracy) customized for TOURney. Link from login.html footer and home.html footer. Unblocks the entire business track.
Build plan: Generate boilerplate ToS + Privacy via Termly free tier. Write as tos.html + privacy.html in root. Add /tos and /privacy rewrites in vercel.json. Link from login.html + home.html footers. Reference in Stripe dashboard business details. ~2h including copy customization.

§5 — Security Review

Findings

Grade: B. Same 5 open findings as May 13. No new findings, no regressions.

Methodology

Inspected all 11 migration files (001–011) for RLS policy text and USING clauses. Grepped innerHTML across all .html and .js files for XSS surfaces. Grepped function esc to verify escape-helper coverage. Grepped _parseMentions for known XSS vector. Read vercel.json for CSP and security header state. Cross-referenced open items from the May 13 full review (5-13-26-claude-review.html) and grades.json security axis history. No new commits since 12c0aad — security posture is unchanged from May 13.

HIGHfeed.html:377 — _parseMentions Stored XSS
_parseMentions(p.message) sets d.innerHTML = str then calls d.innerHTML.replace() to wrap @mentions. The input str is user-generated post content from the feed. HTML tags in the message execute before @mention replacement runs. The esc() helper exists at feed.html:658 but is not applied to str before it enters innerHTML. Any player can store an XSS payload in a feed post — executes for every user who views the feed page.
Fix Plan 1. In _parseMentions, call esc(str) on the input before assigning to d.innerHTML — or refactor to build a DocumentFragment without innerHTML entirely.
2. Grep remaining innerHTML assignments in feed.html not using esc().
3. Re-test with <img src=x onerror=alert(1)> in a feed post — must render as literal text.
HIGHadmin.html:~2044, ~2194 — URL Strings in innerHTML
Two locations in admin.html render a url value directly to innerHTML without calling esc(). If the url value sources from player-editable data (profile URL, course link), this is a stored XSS vector accessible to any admin viewing that panel.
Fix Plan 1. Open admin.html, search for innerHTML near lines 2044 and 2194.
2. Wrap the url value: esc(url) before inserting — or use element.textContent = url if no HTML rendering is needed.
3. Grep all remaining innerHTML in admin.html not guarded by esc().
MEDIUMplayer_accounts — anon SELECT USING(true)
Migration 005_invitations_and_accounts.sql:41: policy "anon read player_accounts" on player_accounts FOR SELECT TO anon USING (true). Any unauthenticated visitor can read all player_accounts rows including billing_status and stripe_customer_id. Exposes monetization data publicly.
Fix Plan 1. New migration 012_tighten_player_accounts_rls.sql.
2. DROP POLICY "anon read player_accounts" ON player_accounts;
3. Replace: CREATE POLICY "authenticated read own player_account" ON player_accounts FOR SELECT TO authenticated USING (auth.uid() = user_id);
4. Verify /player-upgrade still works post-migration (uses authenticated session).
MEDIUMCSP unsafe-inline Nullifies XSS Protection
vercel.json *.html headers CSP: script-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net. The 'unsafe-inline' directive allows inline script execution — the exact attack vector in findings #1 and #2. A CSP without unsafe-inline would block injected scripts at the browser level even before code fixes land. The CSP is present but provides false comfort — it cannot stop inline XSS.
Fix Plan 1. CSP extraction (Council idea #1) is the prerequisite — all inline <script> blocks to external .js files.
2. Once extracted, remove 'unsafe-inline' from script-src in vercel.json.
3. Refactor any inline event handlers (onclick etc.) to addEventListener in external JS.
4. Test: inline script injection attempt must produce CSP console error and not execute.
MEDIUMSEND_INSTALL_EMAIL_SECRET Env Var Not Set
send-install-email v4 has a SEND_INSTALL_EMAIL_SECRET webhook gate — the code is deployed correctly, but the environment variable is not set in the Supabase project dashboard. The webhook DB header also needs updating to send the secret. Without both, the gate does not function.
Fix Plan (Rob manual action) 1. Supabase dashboard → Project Settings → Edge Functions → Environment Variables.
2. Add SEND_INSTALL_EMAIL_SECRET = strong random value (openssl rand -base64 32).
3. Update the DB webhook that triggers send-install-email — add the secret in the Authorization header.
4. Test: fire webhook without header → must get 401. Fire with header → must proceed.
INFOinvitations — anon UPDATE Accepted Design
005_invitations_and_accounts.sql:20 — "anon update own invitation" USING(true) with no ownership predicate. Flagged CRITICAL in May 7 review. Accepted design: the invite flow requires anon users to redeem tokens before auth exists. The accept-invitation edge function validates the token before any write occurs. Monitor for abuse patterns.
Long-term recommendation: Add a token-match predicate to the policy so the RLS itself enforces ownership, removing reliance on the edge function as the sole gate. Acceptable risk for now.
